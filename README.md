# Calendar Agent Backend

사람이 정리한 일정 JSON을 가져와 시간 충돌을 검토하고, 충돌이 해결되면 즉시 내부 캘린더에 등록하는 Python CLI입니다. 중복 검사는 필요할 때 별도로 실행하며 등록을 막지 않습니다. 원본 입력 JSON과 앱이 관리하는 저장소는 서로 다른 파일입니다. 첫 검토에서는 이동시간 부족을 충돌로 판정하지 않습니다.

## 실행

Python 3.10 이상과 Ollama 실행 환경, `qwen3.5:4b` 모델을 사용합니다. 추가 Python 패키지는 필요하지 않습니다.

```powershell
cd C:\Users\chw11\Desktop\FR\calendar_agent_backend
python cli.py
```

메뉴는 다음 기능으로 구성됩니다.

1. **일정 데이터 가져오기 + 충돌 검토**: `examples/workflow.demo.input.json`을 원본으로 읽어 우리 저장소에 추가합니다. 원본 파일은 수정하지 않습니다. 각 새 일정에 `registered_at`을 붙입니다. 앱 안의 일정끼리 시간이 겹치면 양쪽을 보여주고, 바꿀 일정을 선택하게 합니다. 시간만 변경하거나 삭제한 뒤 다시 검사합니다. 시간이 누락된 일정은 시작·종료 시각만 입력받습니다. 시간 겹침과 시간 누락이 해결되면 바로 내부 캘린더에 등록합니다. 이동시간 부족과 중복 후보는 이 단계에서 확인하지 않습니다.
2. **저장된 일정 수정**: 일정 번호로 불러와 제목·유형·사람·소속·시간·장소·내용을 수정합니다. 저장 후 충돌만 다시 검사하고, 충돌이 해결되면 내부 캘린더에 다시 등록합니다.
3. **저장소 초기화**: 확인을 받은 뒤 우리 저장소 JSON만 초기화합니다. 원본 입력 JSON은 변경하지 않습니다.
4. **메인 일정 타임라인 / 현황**: 앱 내부에 등록된 확정 일정만 날짜별로 확인합니다. 각 항목에 날짜와 시작·종료 시각을 표시합니다.
5. **AI 일정 검토 목록**: 전체/Gmail/Notion/충돌 없음 필터로 일정, 신뢰도(입력 JSON에 있을 때), 최근 이슈를 봅니다.
6. **Inbox 원문 목록 / 미리보기**: Gmail/Notion 등 원문 레코드의 처리 상태와 `raw_text`를 확인합니다.
7. **일정 후보 무시 처리**: 일정 후보를 내부 확정 목록에서 제외하고 연결된 원문을 처리 완료로 표시합니다.
8. **저장된 일정 중복 검사**: 새로 가져오지 않고 현재 내부 일정끼리 Ollama로 비교하고 후보를 하나씩 판정합니다. 이 검사는 선택 사항이며 일정 등록 상태를 바꾸지 않습니다. 사용자가 같은 일정이라고 판단하면 중복본을 내부 저장소에서 제거합니다.
9. **날짜별 AI 일정 요약**: 내부 확정 일정이 있는 날짜를 번호 목록으로 보여줍니다. 날짜 번호를 선택하면 해당 날짜 일정을 로컬 Ollama가 시간순으로 요약합니다.

메뉴에서 작업 하나가 끝나면 다시 선택창으로 돌아옵니다. 1번의 충돌 검토만 완료하면 일정이 내부 캘린더에 등록됩니다. 8번 중복 검사는 나중에 별도로 실행할 수 있고, Ollama 연결 여부는 등록에 영향을 주지 않습니다. 외부 Google Calendar 일정은 가져오거나 충돌·중복 검사에 사용하지 않습니다. Gmail/Notion의 실제 API 수집과 원문 자동 일정 추출은 아직 연결하지 않았고, 지금은 구조화 JSON 및 `raw_text`를 시험할 수 있습니다. Google Calendar API 쓰기도 연결하지 않았습니다.

## 저장 파일

- `examples/workflow.demo.input.json`: 가져오는 원본 예제 데이터. 일부 항목에 Inbox 원문 샘플 포함
- `data/registered_events.json`: 우리 측 별도 저장소. 일정, 등록 시각, 일정/원문 상태, 중복 판단을 저장
- `data/calendar_agent.sqlite3`: 이전 CLI에서 사용하던 SQLite 파일. 현재 메뉴에서는 사용하지 않습니다.

가져오기 이력은 일정과 연결된 원문 내용의 fingerprint로 기록합니다. 이미 검토한 내용이 같으면 1번에서 다시 검토하지 않습니다. 새 일정이나 원문/일정 내용이 바뀐 일정만 검토하고, 검토 중단된 일정은 재실행 시 이어서 확인합니다. 같은 `event_id`의 기존 로컬 수정과 최초 등록 시각은 동일 입력 재가져오기에서 유지됩니다. 저장 위치를 바꾸려면 `python cli.py --store 경로`를 사용합니다.

예제 입력에는 일정 10건이 들어 있습니다. 12월 3일에 4건, 12월 4일과 5일에 각각 3건을 배치했습니다. 12월 3일의 `고객사 ABC 프로젝트 킥오프`와 `보고서 집중 작업`만 의도적으로 겹치게 했으므로, 충돌 검토에서 집중 작업을 삭제하면 총 9건이 남고 세 날짜에 각각 3건씩 배치됩니다. 연계 사례는 `evt-001 → evt-003 → evt-007`(킥오프와 후속 미팅), `evt-004 → evt-010`(치과 검진과 후속 치료)입니다. 현재 저장소에 이전 예제 일정이 남아 있다면, 새 10건으로 깨끗하게 시작할 때는 메뉴 3으로 우리 저장소를 초기화한 뒤 메뉴 1로 가져오세요.

## 입력 JSON

입력 계약은 [schemas/input.schema.json](schemas/input.schema.json), 처리 로직 개요는 [workflow.md](workflow.md)를 참고합니다. 날짜와 시각은 시간대 오프셋을 포함한 ISO 8601을 사용합니다. 예: `2026-12-03T15:00:00+09:00`.

자동 내부 등록은 우리 JSON 저장소의 확정 상태를 바꾸고 메인 타임라인에 표시합니다. Google Calendar로 일정을 생성·수정·삭제하지 않습니다.
